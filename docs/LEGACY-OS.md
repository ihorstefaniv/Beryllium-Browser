# Beryll на старих Windows: варіанти

Статус: пропозиція, листопад 2026. Нічого з описаного нижче ще не реалізовано.

## Чому на старих ОС ламаються сайти й відео

| ОС | Що зараз з Beryll | Причина |
|---|---|---|
| Windows 10 / 11 | Працює | WebView2 оновлюється разом з Edge (зараз Chromium 156) |
| Windows 8 / 8.1 / 7 | Рушій застряг на Chromium 109 (січень 2023) | Microsoft припинила WebView2 і Edge після 109, оновлень безпеки немає |
| Vista / XP | Не запускається | Немає WebView2, а .NET максимум 4.0 (нам потрібен 4.6.2+) |

Старі браузери ламаються на сайтах з трьох причин:
1. **Застарілий JavaScript.** Сайти збирають під останні 2–3 роки браузерів, і нові можливості мови в старому рушії просто падають.
2. **Відео.** Сучасні плеєри (YouTube, Vimeo, HLS-плеєри) вимагають MSE, WebCodecs, VP9 або AV1 і нові API.
3. **HTTPS.** Системні сертифікати й TLS у XP/7 застаріли. Chromium має власний TLS (BoringSSL) і своє сховище кореневих сертифікатів, тому сучасний Chromium цю проблему обходить.

Тобто треба приносити **сучасний рушій**, а не латати старий.

## Рушій для старих ОС: Supermium

[Supermium](https://github.com/win32ss/supermium) — відкритий форк Chromium (ліцензія BSD, як у Chromium), перенесений на старі Windows.
- Остання стабільна версія 144 (червень 2026). Підтримує XP SP1+ / Server 2003 SP1+, Vista, 7, 8, 8.1, 10.
- Кодеки H.264/AAC є, DRM (Widevine) працює на Win7+.
- Досі підтримує розширення Manifest V2, тобто повний uBlock Origin.
- Вимоги до процесора: 32-bit потребує SSE2 (Pentium 4 / Athlon 64 і новіші), 64-bit потребує SSE3.

## Варіанти

### A. «Beryll Legacy»: готовий пакет на Supermium (швидкий старт)
Portable-zip: Supermium + наш профіль за замовчуванням.
- Приватність як у Beryll: блокування сторонніх cookies, DuckDuckGo, без телеметрії, Do Not Track / GPC.
- uBlock Origin і **h264ify**: примусово H.264 замість VP9/AV1. Для старих ПК це **найбільший виграш у відео**, бо H.264 декодує відеокарта навіть 2008–2012 років, а VP9/AV1 лягає на процесор.
- Сторінка нової вкладки Beryll як розширення, іконка Be, лаунчер з прапорцями під слабке залізо: обмеження процесів рендерингу, `--disk-cache-size`, вимкнення фонових служб.
- Плюси: працює одразу на 7/8/XP, сучасні сайти й відео.
- Мінуси: інтерфейс Supermium/Chrome, не наш. Оновлення рушія доведеться перепаковувати. Розмір ~120–150 МБ.
- Обсяг роботи: невеликий (дні).

### B. Наш інтерфейс + рушій окремим процесом («костиль», перевірено)
Beryll малює свій інтерфейс (вкладки, адресний рядок, щит), а Supermium працює як «безголовий» рушій:
1. Рушій запускається в `--app`-режимі з власним `--user-data-dir` і `--remote-debugging-pipe` (або портом на 127.0.0.1).
2. Вікно рушія вбудовується в наше через `SetParent` (як WS_CHILD).
3. Керування йде через Chrome DevTools Protocol: навігація, назад/вперед, заголовок, URL, завантаження, дозволи, блокування запитів.

**Дослід 05.11.2026 (Win11, Edge 156 як заміна Supermium):** вікно рушія вбудувалося в WinForms-форму, сторінка відмалювалась, DevTools віддав заголовок і URL вкладки. Лишилась власна смужка заголовка app-вікна, вона ховається зсувом вікна вгору на її висоту.

Що треба зробити:
- Інтерфейс `IEngine` у Beryll: дві реалізації, WebView2 (Win10/11) і CDP+Supermium (7/8/XP). Інтерфейс спільний.
- Власний WebSocket-клієнт на `TcpClient`: `ClientWebSocket` у .NET працює лише з Win8, на 7 і XP його немає. Або pipe-транспорт.
- Окрема збірка під .NET 4.0 без WebView2 (умовна компіляція) для XP/Vista. Win7 має .NET 4.8, там усе як є.
- Фокус клавіатури, гарячі клавіші, DPI, спливні вікна й діалоги рушія між двома процесами. Це найбільше дрібної роботи.

- Плюси: один Beryll з однаковим інтерфейсом на всіх ОС, рушій сучасний.
- Мінуси: складніше й крихкіше за A, особливо фокус і клавіатура. Рушій усе одно треба тягнути в пакеті.
- Обсяг роботи: тижні.

### C. WebView2 109 для Win7/8 (не рекомендується)
Наш інтерфейс як є, але рушій 2023 року без оновлень безпеки: саме ті проблеми, від яких хочемо піти. XP не покриває.

### D. Зібрати CEF із патчами Supermium (нереально соло)
«Справжнє» вбудовування рушія як бібліотеки. Збірка Chromium вимагає ~100+ ГБ, потужну машину, години компіляції, і цей форк доведеться підтримувати постійно. Для одного розробника не варто.

### Альтернатива для XP: Firefox-гілка
Mypal / Serpent (UXP) працюють на XP, але відстають від сучасного вебу більше, ніж Supermium. Сенс є лише як запасний варіант.

## Рекомендація й порядок

| Пакет для завантаження | ОС | Рушій | Коли |
|---|---|---|---|
| `Beryll` | Win10 / 11 | WebView2 (системний) | Є зараз |
| `Beryll-Legacy-x64` | Win7 / 8 / 8.1 (64-bit) | Supermium 144 | Етап 1: варіант A |
| `Beryll-Legacy-x86` | Win7 / 8 (32-bit), Vista, XP | Supermium 144 x86 | Етап 2, XP експериментально |
| Beryll з `IEngine` | 7 / 8 / XP | Supermium через CDP | Етап 3: варіант B, коли A себе виправдає |

Етап 1 одразу вирішує проблему «сайти й відео не працюють» на Win7. Варіант B переносить наш інтерфейс поверх того самого рушія, тож робота з етапу 1 (профіль, розширення, прапорці) не пропадає.

Що врахувати на XP: машини з XP зазвичай мають 1–2 ГБ RAM і Pentium 4 / Core 2. Сучасний Chromium там запуститься, але YouTube вище 480p буде важким навіть з H.264. Тут чесно обіцяти «працює», а не «літає».
